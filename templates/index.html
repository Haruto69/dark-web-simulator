How a deterministic rewind works

Every module runs the same underlying sequence. The starting state S0 is fixed and recorded; the "rewind" is not a restart, it is a return to that exact recorded state, verified before your second decision is allowed to run.

  1. S0

    Starting state S0

    A fixed scenario state -- inbox, prompt or workstation -- identical for every learner and recorded before any decision is made.

  2. 1

    Factual decision Your path

    You make a real decision from S0 -- the one you would actually make.

  3. 2

    Factual consequence

    That decision plays out to a real, simulated technical consequence.

  4. ↻

    Rewind Deterministic

    The system returns to S0 and verifies it matches the originally recorded state exactly, before continuing.

  5. 3

    Alternative decision Rewind path

    From the same verified S0, you take a different decision.

  6. 4

    Alternative consequence

    That different decision produces its own consequence, from the identical starting point.

  7. ≡

    Compare Side by side

    Both paths, both consequences, and exactly what differed between them -- laid out together.
