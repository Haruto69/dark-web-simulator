These screens exist so the RewindSec 2.0 product can be used before it is built. Every message, file, contact and consequence below is authored fixture data. Nothing behind them runs: there is no simulation session, no scheduler, no context ledger, no scoring engine and no persistence.

The question to answer while using them is not whether the code is right. It is whether this is the product worth building.

What is deliberately not here

  • No automatic rewind. A decision that goes badly stays gone badly, and the workstation is never rolled back to a state before it.
  • No Easy / Medium / Hard control. The learner picks focus and mode; the scaffolding profile is derived.
  • No threat labels inside the workstation. A hostile message looks like work, because that is the whole problem.
  • No verdict button. Investigation happens through Directory, Messages, mail history and the Authenticator's own records.

Learner surfaces also carry integrity controls: copy, cut and paste are blocked everywhere except Notes, and a PrintScreen key raises a short notice. Both are deterrence. A web page cannot prevent an operating-system screen capture, and nothing in the interface claims it can. Trainer screens are unaffected.

The decision this prototype is asking you to make

Architecture §12 leaves one feature explicitly unfrozen.

After an unsafe decision in Practice or Simulation, the consequences unfold in the workstation, and once the chain settles a blocking screen explains what happened, what evidence was already available, and what a safer process would have produced. It is not a rewind and it does not claim the decision was undone.

Use it a few times, then decide: keep it, redesign it, or remove it. It is built so that removing it is a three-line change that leaves the persistent consequences untouched.
